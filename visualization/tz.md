# ТЗ: Интерактивная визуализация эволюции тем в письмах и дневниках Л. Н. Толстого

**Исправлено под реальность проекта leotolstoy (сентябрь 2026).** Исходное ТЗ
писала сторона, не видевшая проект; ниже — скорректированная версия. Что именно
исправлено и почему — см. «Отличия от исходного ТЗ» в конце. Реализация — в
`src/` + `run.py` этого каталога; страницы — в `out/`.

## 1. Цель

По готовым эмбеддингам текстовых фрагментов построить красивую интерактивную
визуализацию, показывающую дрейф смыслов во времени:

1. **Карта смыслов с фильтром по годам** (DataMapPlot).
2. **Алювиальная диаграмма**: как тематические кластеры перетекают из эпохи в эпоху.

Названия тем — осмысленные, сгенерированные LLM, а не списками слов. Итог:
статический HTML, открывающийся двойным кликом без сервера. Главный подпроект
(чат) не меняется: визуализация — изолированный подпроект в `visualization/`.

## 2. Входные данные

Индексы читаются **напрямую из `../index/`, только на чтение** (копий не делаем,
~190 МБ зря не дублируем). `index.qwen3-embedding-8b/` — НЕ существует (устаревший
внешний индекс, для визуализации игнорируется).

Фактическая структура (проверено, сентябрь 2026):

- `../index/vectors.npy` — (54393, 384) float32, **уже L2-нормализованы**
  (норма 1.0 у всех; сборщик индекса это гарантирует — в load.py ассерт).
- `../index/chunks.json` — 54393 чанка: письмо 40115, дневник 14278. Каждый
  чанк: `{"text", "source", "meta"}`; поля meta: vol, type, date, year, entry,
  title, bibl, num, pages, ed_year, first_pub, old_orth, **to** (адресат,
  у 38883/40115 писем), **place** (у 39578), doc, chunk.
- Годы в meta **грязные**: 49166 — чистые 4-значные; 5017 — диапазоны
  («1848–1848», «1888–1900»); 210 — отсутствуют; 3 аномалии «2012» (битая
  дата в TEI, т. 80). Нормализация: первый 4-значный год диапазона; год > 1910
  (смерть Толстого) или отсутствующий → «без даты» (сентинел −1).
- Десятилетия: 1840: 327, 1850: 4891, 1860: 2470, 1870: 3423, 1880: 7794,
  1890: 16276, 1900: 16079, 1910: 2920.

Первым шагом run.py печатает сводку (формы, типы, десятилетия, пропуски,
аномалии) в `cache/data_report.txt`.

  (LLM_API_KEY / LLM_BASE_URL / LLM_MODEL, OpenAI-совместимый
  `/chat/completions` через httpx). Никакого пакета anthropic и отдельного

## 4. Структура проекта

```
visualization/

  pyproject.toml       # отдельный uv-проект
  .python-version      # 3.12
  .gitignore           # .venv/, cache/, out/ (артефакты — не в git)

                       # --standalone, --k-per-epoch, --link-threshold,
                       # --min-epoch-size
  src/
    load.py            # чтение ../index/ (read-only), ассерты, нормализация годов
    palette.py         # общая палитра тем (карта + Sankey, валидирована на CVD)
    project.py         # UMAP 2D + 10D + PNG-скетч
    cluster.py         # HDBSCAN (с фолбэком на KMeans) + KMeans по эпохам + связи
    label.py           # c-TF-IDF (pymorphy3) + LLM-названия через .env
    build_map.py       # DataMapPlot → out/map.html
    build_alluvial.py  # Plotly Sankey → out/alluvial.html
    build_site.py      # out/index.html (вкладки, iframe)
  cache/               # промежуточные результаты (npy/json) — не в git
  out/                 # итоговые html + sketch_umap2d.png — не в git

Каждый тяжёлый шаг (UMAP, кластеризация, c-TF-IDF, LLM-названия, сборка страниц)
кэшируется в `cache/`/`out/`. Повторный запуск пересчитывает только
отсутствующее; `--force STEP` (через запятую, или `all`) сбрасывает кэш шага.

## 5. Пайплайн

### 5.1 Проекции
- Векторы уже L2-нормализованы (ассерт в load.py, не вычисление).
- UMAP 2D: `n_neighbors=30, min_dist=0.05, metric="cosine", random_state=42`
  (для карты).
- UMAP 10D: `n_neighbors=30, min_dist=0.0, metric="cosine", random_state=42`
  (только для кластеризации).
- После UMAP — PNG-скетч `out/sketch_umap2d.png` (цвет — десятилетие).

### 5.2 Глобальные кластеры (для карты)
- HDBSCAN на 10D-проекции, `min_cluster_size=60, min_samples=10`.
- Шум > 60% → пересчёт с `min_cluster_size=30` (с сообщением).
- **Цель: 10–30 осмысленных кластеров.** Реальность: корпус однороден, HDBSCAN
  даёт либо один блоб на 54 тыс. чанков (mcs=60), либо крошку из ~114 кластеров
  с шумом ~67% (mcs=30). Поэтому при вырождении (вне 10–30 или шум > 60%)
  — **фолбэк на KMeans(k=24) по исходным 384D-векторам** (они нормализованы,
  евклидова ≈ косинусная): детерминированно, все точки размечены, «Прочее»
  не нужно. Метод попадает в отчёт и в `cache/hdbscan.json`.
- По 3 примера текста на кластер — в отчёт (`cache/cluster_report.txt`).

### 5.3 Кластеры по эпохам (для алювиальной диаграммы)
- Эпоха = десятилетие; эпохи меньше `--min-epoch-size` (300) чанков сливаются
  с предыдущей (1840-е, 327 чанков, остаются отдельной эпохой).
- Внутри каждой эпохи: KMeans на исходных 384D-векторах, K=6
  (`--k-per-epoch`). Для каждого (эпоха, кластер): L2-нормализованный центроид,
  размер, диапазон лет.
- Связи между соседними эпохами: косинусная близость центроидов ≥
  `--link-threshold` (0.75), не более 3 связей на узел. Вес связи =
  близость × размер исходного кластера.

### 5.4 LLM-названия тем
Для каждого глобального кластера и каждого узла эпохального кластера:
- 8 фрагментов, ближайших к центроиду (косинус), обрезанных до 400 символов.
- Топ-10 лемматизированных слов по c-TF-IDF: токенизация + стоп-слова;
  pymorphy3-лемматизация только ~2000 самых частых словоформ корпуса (полная
  лемматизация ~2.5 млн слов — десятки минут, а в топ-10 попадают частые слова;
  редкие — имена собственные, им лемма не нужна).
- Промпт (на русском): короткое название (2–4 слова) + однострочное описание,
  строго JSON `{"title": "...", "description": "..."}`. Для узлов эпохи в промпт
  передаются уже выданные названия той же эпохи («не повторяйся»); внутри эпохи
  узлы обрабатываются последовательно, эпохи — параллельно.
- Вызов: OpenAI-совместимый `POST {LLM_BASE_URL}/chat/completions` (httpx),
  модель LLM_MODEL из `../.env`, temperature 0.3, max_tokens 300, до 5
  параллельных запросов, 3 ретрая с бэкоффом, парсинг JSON с очисткой от
  ```-обёрток.
- Кэш: `cache/labels_global.json`, `cache/labels_epoch.json`.
- API недоступен/нет ключа → фолбэк на топ-3 термина c-TF-IDF, без падения.

### 5.5 Карта смыслов (DataMapPlot)
- **Фактическая версия: datamapplot 0.7.x (deck.gl).** В ней текст метки — это
  сама метка (массив строк на точку), отдельного `label_text` нет; поиск
  включается `enable_search=True`; `title/sub_title/гистограмма` — параметры
  `render_html`, пробрасываются из `create_interactive_plot` через **kwargs
  (проверяем по фактической сигнатуре, не угадываем).
- Метка точки = LLM-название темы (или «Прочее», если есть шум);
  `label_color_map` — общая палитра из `palette.py`.
- Hover: «ГОД · тип (адресат, место)», ниже — первые 250 символов текста и
  описание темы.
- Временной фильтр: `histogram_data` = годы (1 бин = 1 год; чанки «без даты»
  прижаты к min_year — с явным `histogram_range` числовой путь datamapplot
  0.7.3 падает, это их баг), бруш-выделение периода.
- Тёмная тема (`darkmode=True`), заголовок «Лев Толстой: карта смыслов»,
  подзаголовок с числом фрагментов и диапазоном лет.
- `--standalone`: данные и так встроены (`inline_data=True` по умолчанию);
  JS-библиотеки (deck.gl и пр.) datamapplot грузятся с CDN (unpkg) — полного
  офлайна 0.7.x не умеет, флаг лишь печатает список внешних скриптов. Для
  локального просмотра file:// нужен интернет.

### 5.6 Алювиальная диаграмма (Plotly Sankey)
- Узлы: эпохальные кластеры, подписи = LLM-названия (длинные переносятся <br>).
- Колонки узлов строго по эпохам слева направо (node.x), подписи эпох — над
  колонками (annotations), y внутри колонки — равномерно (arrangement="fixed").
- Цвет узла — по ближайшему глобальному кластеру (косинус центроидов), из той
  же палитры, что и карта → родственные темы одного цвета на обеих вкладках.
- Цвет связи: цвет источника, прозрачность 0.3; вес — близость × размер.
- Hover узла: название, описание, число фрагментов, годы.
- Тёмная тема (#111111, в одном стиле с картой и обёрткой);
  `include_plotlyjs=True` — JS встроен, работает с file:// без интернета.

## 6. Сборка страниц

По умолчанию: **одна страница `out/index.html`** с вкладками «Карта смыслов» и
«Потоки тем» (iframe на `map.html`/`alluvial.html`), переключение без
перезагрузки, тёмный фон, минималистичный заголовок и 2 предложения «как
читать» под каждой вкладкой. `--split` — только `out/map.html` и
`out/alluvial.html`, без обёртки.

**Запуск:** `make visualization` из корня проекта (или `uv run python run.py`
отсюда). run.py сверяет штамп index/ (mtime+size векторов/чанков) с кэшем:
индекс сменился — полный пересчёт, нет — секунды из кэша. Работает одинаково
локально (просмотр двойным кликом по out/index.html) и на сервере (там — после
`make embeddings`, для обновления https://verbatis.ru/viz/; статику отдаёт
Caddy, route /viz/* в корневом Caddyfile, deploy.sh возит его и делает reload).

## 7. Критерии приёмки

1. `uv sync && uv run python run.py` на чистом клоне собирает `out/index.html`
   без ручных шагов (кроме ключа LLM — он и так в корневом `.env`).
2. Повторный запуск — секунды благодаря кэшу.
3. На карте: подписи кластеров осмысленные, работает поиск, hover показывает
   текст, гистограмма по годам фильтрует точки.
4. На алювиальной: колонки по эпохам, читаемые подписи, нет «паутины»
   (среднее число исходящих связей 1–3), цвета согласованы между эпохами и
   с картой.
5. Названия тем различимы между собой; нет дубликатов внутри одной эпохи.
6. run.py печатает отчёт: метод кластеризации, долю шума, число кластеров,
   число эпох/узлов/связей, число LLM-вызовов и фолбэков, время шагов.
7. Код простой и линейный: без лишних абстракций; параметры через argparse
   в run.py.

## 8. Правила работы для агента

- Сначала загрузи и осмотри данные (раздел 2), покажи сводку, затем реализуй шаги.
- Пиши **полные файлы**, а не патчи.
- Промежуточные проверки: после UMAP — PNG-скетч проекции; после кластеризации —
  по 3 примера текста на кластер, чтобы глазами убедиться в осмысленности.
- **Не меняй файлы в `../index/`, `../data/`, `index.qwen3-embedding-8b/` и
  корне проекта.** Всё — внутри `visualization/`.

## Отличия от исходного ТЗ (что и почему исправлено)

| Исходное ТЗ | Как сделано | Почему |
|---|---|---|
| Claude API: пакет anthropic, ANTHROPIC_API_KEY, модель claude-sonnet-4-6 | OpenAI-совместимый провайдер из корневого `../.env` (LLM_*, deepseek-chat), httpx | Модели claude-sonnet-4-6 не существует; в проекте уже есть рабочий LLM-конфиг и ключ; ноль новых зависимостей |
| Шаг «L2-нормализовать эмбеддинги» | Ассерт в load.py | Векторы уже нормализованы сборщиком индекса (проверено: нормы = 1.0) |
| Годы — «диапазон годов» без деталей | Нормализация: первый год диапазона; >1910/нет → «без даты» | В meta 5017 диапазонов («1848–1848», «1888–1900»), 210 пропусков, 3 битые даты «2012» |
| Адресат «addressee» | Поле `to` (+ `place`) | Так названо в chunks.json (проверено) |
| `np.load(..., allow_pickle=True)` | Обычный np.load | vectors.npy — чистый float32, pickle не нужен |
| Папка `visualization/data/` с копиями .npy | Чтение `../index/` напрямую (read-only) | Не дублировать ~190 МБ; правило «индекс не менять» |
| Python 3.11+ / стек из списка | Python 3.12, отдельный uv-проект в visualization/ | Корневой pyproject не трогаем (иначе numba/umap попадут в Docker-образ сервера) |
| HDBSCAN всегда, шум > 60% → mcs=30 | HDBSCAN + фолбэк на KMeans(24) при вырождении | На этом корпусе HDBSCAN даёт блоб либо крошку с шумом 67%; KMeans покрывает все точки и укладывается в цель 10–30 |
| `histogram_data`+`histogram_range` | Только `histogram_data` (без range), «без даты» → min_year | С явным range числовой путь datamapplot 0.7.3 падает (баг: edges на 1 короче индекса) |
| `inline_data=True` как опция --standalone | inline_data — дефолт; --standalone печатает внешние скрипты | В 0.7.x данные всегда можно встроить; полный офлайн (без CDN) не поддержан |
| Палитра «по хешу названия» | Фиксированная палитра 24 цветов по id глобального кластера (карта + Sankey), валидирована на CVD/контраст | Хеш названия нестабилен между прогонами и не даёт согласованности с картой; палитра проверена валидатором (OKLab ΔE, дейтеранопия, контраст на тёмном) |
